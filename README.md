# 8051 Basketball Timer and Scoreboard

基于 STC89C52RC 的篮球计时计分器。

一个使用 C 语言编写的 51 单片机练习项目，实现篮球比赛倒计时、双队计分、蜂鸣器提示、PWM 呼吸灯、OLED 图片显示，以及电脑串口查询和改分。

项目采用 **PlatformIO + SDCC + stcgal** 开发，代码按功能拆分为独立模块，并提供面向初学者的中文注释。目标硬件为 **STC89C52RC、12 MHz 外部晶振、12T 模式**。

## 功能概览

- **比赛计时**：四位数码管显示 `MMSS`，支持加减一分钟、开始/暂停、双键复位。
- **双队计分**：四位数码管显示 `AABB`，两队分别支持 `00～99` 分、交换比分和清零。
- **按键检测**：周期采样消抖，支持单键及双键组合，组合键优先处理。
- **蜂鸣器提示**：剩余 30 秒时短鸣三次，最后 10 秒间歇提示，最后 5 秒加快。
- **PWM 呼吸灯**：P2.5 外接 LED，最后 30 秒开始呼吸，最后 10 秒加快。
- **OLED 显示**：软件 I²C 驱动 128×64 单色 OLED，上电显示自定义位图，保留整屏 180° 旋转配置。
- **串口交互**：向电脑回报时间、比分、运行状态和最终结果，支持从电脑修改比分。
- **方波输出**：P2.4 输出约 1 kHz 方波，便于测量定时器输出。

上电默认状态：U3 显示 `0100`，U2 显示 `0000`，倒计时处于暂停状态。

## 硬件与接线
### PCB文件

本项目使用嘉立创EDA绘制PCB。需要注意的是，关于呼吸灯部分，由于绘板失误只能飞线解决，具体方法见照片。

### 主控与显示

| 硬件 | 连接 | 说明 |
| --- | --- | --- |
| STC89C52RC | 12 MHz 外部晶振 | 使用 12T 模式 |
| 两组四位数码管段线 | P0.0～P0.7 | 共用 a～g、dp 段线；高电平点亮 |
| U3 计时数码管位选 | P2.0～P2.3 | 低电平选中，显示 `MMSS` |
| U2 计分数码管位选 | P1.0～P1.3 | 低电平选中，显示 `AABB` |
| 蜂鸣器驱动控制 | P1.4 | 高电平开启板上驱动电路 |
| 外接呼吸 LED | P2.5 | LED 正极经限流电阻接 P2.5，负极接 GND |
| 方波输出 | P2.4 | 约 1 kHz |

本程序的段码和位选逻辑针对当前 PCB。使用其他数码管或开发板时，需要核对共阳/共阴、段线顺序和位选有效电平。

### OLED

| OLED 信号 | 单片机连接 |
| --- | --- |
| SCL | P1.7 |
| SDA | P1.6 |
| GND | 公共 GND |
| VCC | 按实际模块的额定电压供电 |

当前使用 I²C 地址 `0x3C`，发送的写地址字节为 `0x78`。程序适配当前实物验证可用的 128×64 单色屏及其初始化指令序列，不能据此保证兼容所有 OLED 控制芯片。

当前 PCB 使用 5 V 逻辑电平。示例实物由使用者确认供电和信号端均兼容 5 V；换用 3.3 V 模块时，应按其手册匹配供电与 I²C 电平。仅 VCC 可接 5 V，不等于 SCL/SDA 也能承受 5 V。

### USB 转串口

```text
单片机 P3.1 / TXD  ->  转换器 RXD
单片机 P3.0 / RXD  <-  转换器 TXD
单片机 GND        ---  转换器 GND
```

串口发送与接收交叉连接，两端共地。烧录和程序运行时的串口通信共用这组引脚。

## 按键操作

| 按键 | 引脚 | 功能 |
| --- | --- | --- |
| SW8 | P3.7 | 松开后增加一分钟 |
| SW3 | P3.2 | 松开后减少一分钟 |
| SW4 | P3.3 | 确认按下时开始/暂停 |
| SW9 | P1.5 | 松开后 A 队加一分 |
| SW5 | P3.4 | 松开后 A 队减一分 |
| SW6 | P3.5 | 松开后 B 队加一分 |
| SW7 | P3.6 | 松开后 B 队减一分 |
| SW8 + SW3 | — | 恢复最近手动设定的时间，并暂停 |
| SW9 + SW5 | — | 交换 A、B 两队比分 |
| SW6 + SW7 | — | 两队比分清零，计时状态不变 |

- 按键接地，低电平表示按下。通常每 10 ms 采样一次，连续三次相同后确认状态变化。
- 六个参与组合的按键在松开后执行单键动作；确认组成双键后，取消对应的单键动作。
- 双键允许先后按下，但消抖后需要有同时按住的时间；每组双键全部松开后才能再次触发。
- 倒计时上限为 `5999` 秒，即 `99:59`。加减一分钟前会检查边界，超出时保持原值。
- 运行中也可以加减一分钟，秒数部分不变；调节后的时间成为新的复位目标。
- 归零后按 SW4 会尝试从保存的设定时间重新开始；若设定时间也是零，需先按 SW8 加时。

## 声光提示

### 蜂鸣器

| 状态 | P1.4 控制输出 |
| --- | --- |
| 刚到 `00:30` | 三次短鸣，每次约 100 ms |
| 剩余 10～6 秒 | 每 400 ms 一个周期，鸣叫 180 ms |
| 剩余 5～1 秒 | 每 200 ms 一个周期，鸣叫 90 ms |
| 暂停或归零 | 关闭输出 |

### 外接呼吸灯

PWM 每片为 `250 μs`，32 片组成 `8 ms` 周期，重复频率约为 `125 Hz`。亮度等级为 `0～32`，共 **33 级**。

| 状态 | LED 行为 |
| --- | --- |
| 剩余时间大于 30 秒 | 熄灭 |
| 剩余 30～11 秒 | 每 31 ms 改变一级，约 1984 ms 一次完整呼吸 |
| 剩余 10～1 秒 | 每 12 ms 改变一级，约 768 ms 一次完整呼吸 |
| 暂停或归零 | 熄灭，并复位呼吸进度 |

一次完整呼吸是 `0 -> 32 -> 0`，共改变 64 次。当前实现允许在 PWM 周期中途更新亮度等级，31/12 ms 不要求与 8 ms 周期对齐。

## 编译与烧录

### 1. 准备工具

使用 VS Code 和 PlatformIO IDE，另准备可以从终端调用的 `stcgal`。如果使用 PlatformIO 命令行，下文使用 `pio` 命令。

在包含 `platformio.ini` 的项目根目录打开终端：

```sh
pio run
```

PlatformIO 根据配置安装对应平台及 SDCC 工具链。正式固件生成于：

```text
.pio/build/STC89C52RC/firmware.hex
```

### 2. 选择本机串口与烧录工具

`platformio.ini` 使用通用的 `stcgal` 命令，不包含开发机用户名、工具绝对路径或固定串口号。先确认 `stcgal` 可以从终端直接运行，并让启动 VS Code 的环境也能找到该命令。

```sh
stcgal --help
pio device list
```

从设备列表选择实际连接的串口。多个串口并存时，应通过下一节的 `--upload-port` 明确指定。

```ini
upload_command = stcgal -P stc89 -p $UPLOAD_PORT -b 9600 $SOURCE
```

串口名称随系统和连接方式变化，请使用本机检测结果。需要自定义编辑器或本机配置时，可放在被 Git 忽略的配置文件中；`platformio.local.ini` 不会自动加载，使用它时应自行配置 `extra_configs`。

`board_build.f_cpu = 12000000L` 是编译配置；实际晶振频率和芯片 12T 工作模式也需要与固件一致。

### 3. 写入板子

先关闭占用同一串口的监视器，然后执行：

```sh
pio run -t upload --upload-port <实际串口名>
```

将 `<实际串口名>` 替换为设备名，不保留尖括号。也可以在 PlatformIO 中选择本机上传端口，再点击 Upload。

操作顺序：

1. 保持电脑侧 USB 和板上烧录线连接。
2. 等待 `Waiting for MCU, please cycle power`。
3. 用板上 SW2 断电约 3 秒，再重新上电。
4. 保持供电和接线稳定，等待完整写入及 `Setting options: done`；通过 PlatformIO 上传时还会显示成功状态。
5. 烧录成功后重新上电，检查 U3=`0100`、U2=`0000` 和 OLED 画面。

本板使用断电重上电进入下载流程，按 Reset 不一定能替代完整的上电过程。SW2 以外的串口信号可能导致残余供电，必要时在烧录器等待阶段完全断开并恢复板端供电连接。

## 电脑串口交互

烧录结束并释放串口后，使用任意串口终端，配置为：

```text
4800 baud / 8 数据位 / 无校验 / 1 停止位 / 无流控
```

PlatformIO 命令行示例：

```sh
pio device monitor --port <实际串口名> --baud 4800
```

**运行时通信的 4800 与烧录的 9600 是两个不同的速率设置。**

### 状态与结果输出

上电以及时间、比分或运行状态变化时，程序安排发送状态，例如：

```text
TIME=00:59 A=12 B=08 RUN=1
```

`RUN=1` 表示计时中，`RUN=0` 表示暂停。倒计时结束时先安排 `00:00` 状态，再安排结果：

```text
TIME=00:00 A=12 B=08 RUN=0
FINAL A=12 B=08 WINNER=A
```

胜者字段为 `A`、`B` 或 `DRAW`。结束后修改比分，程序会重新安排结果回报。待发送标记会合并短时间内的多次变化，因此串口输出用于报告状态，不是逐次操作日志。

### 输入命令

每条命令以 **CR、LF 或 CRLF** 结束，小写字母也可识别。

| 命令 | 作用 |
| --- | --- |
| `A=12` | A 队直接设置为 12 分 |
| `B=08` | B 队直接设置为 8 分 |
| `A+` / `A-` | A 队加减一分 |
| `B+` / `B-` | B 队加减一分 |
| `?` | 查询当前状态 |
| `R` | 按当前比分生成结果行；不执行复位 |

设置分数使用两位数字格式，例如 `A=05`。合法范围为 `00～99`；不符合格式的命令会安排回报 `ERR`。

## OLED 图片与参数修改

- 在 [include/board.h](include/board.h) 中设置 `OLED_TEST_ENABLED`：`1` 开启、`0` 关闭 OLED 功能。
- [src/oled_image.h](src/oled_image.h) 保存图标及文字合成的静态位图，保留姓名与学校缩写，学号显示为 `**********`；更换画面时替换这份数据。
- 图片为 **128×64、1 bit/像素、共 1024 字节**，按 8 页组织，每页 128 列，每字节表示同列连续 8 个像素。
- `__code` 将图片放入程序闪存，避免将整张图片占用到 RAM。
- OLED 上电等待约 200 ms 后初始化并写图一次；屏幕内部保存画面，当前没有运行时比分文字绘制。
- 扫描方向及其他初始化参数在 [src/oled.c](src/oled.c) 中设置。换用其他屏幕时，需同时核对分辨率、控制芯片、地址和电平。

## 程序怎样运行

```text
main.c：端口初始化 -> 串口初始化 -> Timer0 启动 -> OLED 初始化与写图
     |
     +-> while (1)：按需处理按键、显示数据更新和串口收发

scheduler.c：每 250 μs 进入 Timer0 中断
     |
     +-> 更新 P2.4 方波与 P2.5 PWM
     |
     +-> 累计四次，形成 1 ms 节拍
            +-> 数码管扫描
            +-> 倒计时毫秒累计
            +-> 蜂鸣器节奏
            +-> 呼吸灯目标亮度
            +-> 每 10 ms 通知主循环扫描按键
```

建议先看 `main.c`，再看 `scheduler.c`，然后按兴趣阅读 `keys.c`、`breathing.c`、`serial.c` 和 `oled.c`。更详细的文件关系见 [模块说明](模块说明.md)。

## 验证情况与已知限制

- 模块化版本已通过 PlatformIO / SDCC 编译与链接，当前 Flash 使用约 **4465 / 8192 字节**。
- 拆分前后曾在模拟寄存器环境运行 320000 次中断，即 80 秒逻辑时间，比较计时、按键、比分、串口及引脚输出，结果一致；这是逻辑回归，不是实物时序测量。
- 模块化程序已成功写入实物，并确认初始计时/计分显示、OLED 和 SW9 加分正常。完整功能调试记录来自同一硬件上的前期版本，后续更换硬件仍需复测。
- 烧录曾出现 `incorrect frame start` 和 `read timeout`，在 9600 和 4800 下都发生过；重新插紧连接后，9600 完整写入成功。降速不能替代检查供电和接触。
- 当前 PCB 的板载 LED2 已拆除，光提示使用 P2.5 的外接 LED。P1.4 控制的蜂鸣器驱动曾出现带载电平偏低，需要结合实际 Q1、R3 等装配检查；固件本身不能保证修复硬件驱动不足。
- OLED 底层会读取应答，但上层尚未做应答失败重试或自动识别屏幕。
- 软件 PWM 的亮度改变未与周期边界同步；呼吸速度与当前定时器配置绑定。
- 项目使用 SDCC 的 `__code`、`__xdata`、`__sbit`、`__interrupt` 等语法，迁移至其他编译器时需要适配。
